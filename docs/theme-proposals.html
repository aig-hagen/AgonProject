03 · Approved decisions

The implementation contract is settled.

These decisions are intentionally separated from small palette tuning. They define meaning, compatibility, and scope for the production theme.

01

Brand direction · Heritage Blue

Approved. Retain AIG blue and ochre as the identity anchors while correcting contrast, surface hierarchy, and interaction states.

02

Dark mode · First-class theme

Approved. Dark mode uses individually tuned values, not mechanically inverted light colors. Graph, status, focus, and elevation tokens are validated independently in both modes.

03

Export preview · Paper-white in both modes

Approved. White paper and dark ink are explicit document-format tokens in both modes. CodeMirror chrome is themed, while the source and SVG output surface remains print-oriented.

04

Graph presets · Theme-aware semantic variants

Approved. Replace fixed-color presets with semantic variants that map through the active theme. Retain a dedicated high-contrast option; redesign or retire “library” and “minimal” if they cannot preserve meaning in both modes.

04 · Complete role registry

Names describe purpose, never appearance.

These roles become the app’s canonical contract. DaisyUI variables, graph options, CodeMirror extensions, maintenance CSS, and first-paint CSS all consume this source.

05 · Ownership boundaries

Every visible color gets an owner.

Deliberate does not always mean recolored. External and platform colors can remain—but only through an explicit policy and a narrow exception list.

App-owned and tokenized

Must resolve from the chosen theme or an explicit, documented state recipe.

  • DaisyUI theme roles and all component states
  • Graph canvas, editing, evaluation, ranking, and scrollbars
  • CodeMirror chrome and syntax palette
  • Maintenance page, first paint, selection, focus, and shadows

Format-owned and stable

Fixed because the output represents a printable or interoperable document.

  • Paper white and print ink in export previews
  • TikZ package colors after an explicit compatibility review
  • User-authored LaTeX/TikZ colors
  • Transparent SVG masks and click targets

External or platform-owned

Retained as explicit exceptions, with accessible fallbacks where possible.

  • TweetyProject logo and approved institutional marks
  • Native select popups, autofill, and forced-colors mode
  • Browser/OS antialiasing and browser-tab presentation
  • User-agent colors only where custom styling reduces accessibility
